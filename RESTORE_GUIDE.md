# Restore the complete labs and 3D content

7 September 2026 repair. Start here when moving this project to another computer
or server. The earlier source-only ZIP did not contain runtime GLB uploads or a
course-content export.

## 1. Extract and check the labs immediately

Extract into a short path, such as `C:\Sasha` on Windows. The new ZIP uses the
short root folder `SashaLMS` to reduce Windows path-length problems.

From that folder, with Python 3 installed:

```sh
python scripts/preview_labs.py
```

Open **http://127.0.0.1:3412/labs/cbse/index.html**. This entry point includes all
59 supplied simulations and needs no login, database, npm install or external
simulation CDN. Keep the server running while using it. Use HTTP instead of
double-clicking scattered HTML files. The DNA scene is generated by the included
JavaScript; it is not a missing standalone DNA GLB file.

Screen-mode 3D requires WebGL. AR/VR additionally requires a compatible physical
device and a secure origin. Desktop screenshots do not prove hardware XR support.

## 2. Start the LMS

Follow `RELEASE_README.md` and `BUILD.md`, configuring your own environment and
accounts. Back up an existing database before running `alembic upgrade head` in
`backend/`. Head remains 0029; migration 0028 now handles an empty core schema and
tables already created by application startup.

Deploy the frontend and backend from the same commit. The supplied static lab
pages live in `frontend/public/labs/cbse/` and are copied into the frontend build.
Keep the complete `frontend/labs/` source directory when building the app.

## 3. Restore the included model library

Four complete models are bundled in `backend/seed_packs/models/`: Duck,
Textured Box, snub_cube and Sasha-Character. They are identified by checksums.

As an administrator, open a Meiporul/Utporul course's curriculum, choose a 3D
lesson and select **Restore included 3D library** in the model picker. The models
become available in the shared library. Repeating this operation is safe and does
not duplicate the same owner's imported library.

Alternatively, with the backend environment configured:

```sh
cd backend
python restore_model_library.py --owner-id YOUR_EXISTING_ADMIN_ID
```

This uses an existing instructor/admin account and generates new model IDs. It
does not create accounts or copy credentials. Use course backups below to remap
lesson/task references automatically; do not paste old numeric IDs into a new DB.

The original file named **New Lesson** is malformed: its scene field is invalid
and its referenced geometry data is absent. The original bytes are preserved in
the recovery package and identified under `unavailable` in the model catalog.
Re-export that model from its source authoring tool to recover its geometry.

## 4. Restore your course content

The complete local handover ZIP additionally contains `recovered-content/`:

- `courses/`: 13 content-only course backups, tested through an isolated restore.
- `model-recovery/`: all 39 GLB files present when the recovery export ran,
  including optional tiers, detached/test files and the malformed original.
- `content-manifest.json`: file hashes, course titles, warnings and provenance.

Open **Content Studio → Course Upload & Backup**, at
`/instructor/course-packages` or `/admin/course-packages`. Upload each course ZIP,
choose **Detect and preview upload**, then **Restore as new draft course**.
Review the draft and publish intentionally. This preserves existing destination
courses and remaps games, labs, models and quiz 3D tasks to new IDs.

Old projectile-motion, cell identification, equation balancing and neuron lesson
links resolve to the matching supplied simulations. Retired graded quiz labs
become clearly labelled draft lesson investigations, since their replacement
simulations do not provide a graded result. Review quiz grading before publishing.
Quiz 3D assessment tasks retain their configurations and model dependencies.

Raw recovery GLBs are not automatically all published: some are detached or test
files. The normal GLB upload option can import an additional complete model after
review. The four-model library above is the verified, active subset.

## 5. Keep models across redeploys

The development stack mounts the backend directory. Both production Compose
variants now explicitly persist `backend/three_d` at their correct container
paths. A custom deployment can set `THREE_D_ROOT` to a persistent directory.
Back up that directory together with the database. Old Windows model paths are
normalized when read on Linux; new paths use forward slashes. If an optional
mobile model tier is missing, the viewer uses the original model.

The viewer decodes authenticated model bytes and embedded textures directly.
The production Content Security Policy is unchanged.

The GitHub source tree includes the active model assets and restore tools. The
private `recovered-content` supplement is provided in the local complete ZIP,
not committed as live user data. Accounts, enrollments, grades, payments and live
recording history are not included in these course-content backups.
