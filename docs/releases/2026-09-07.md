## Notes for the next developer

- Alembic head is **0029**. The local preview database was migrated after a backup;
  a target installation needs its own backup and migration. Older manuals that say
  there is no Alembic or no frontend test suite are historical.
- Configure provider credentials in the target environment. Firebase API key defaults
  in Docker Compose now come from environment variables. The Android Firebase client
  configuration is public app configuration, not a server service-account credential.
- Test real payment/webhook flows in test mode, verify physical AR/VR hardware,
  and measure intended production load before launch. These were not validated by
  the desktop screenshots or local test suite.
- Offline packs cover text and labs/models; external video/attachments need a
  connection. Production builds emit the service worker; the Vite development
  preview is not an offline-service-worker acceptance environment.
- The video uses conceptual feature cards; `product-captures/` contains genuine
  public LMS captures. These recordings do not demonstrate physical AR/VR devices.
- The existing working tree had removed legacy WordPress plugin/theme files and
  generated preview images. This snapshot preserves that current tree. It does not
  restore the separate legacy WordPress site.

## Export scope and privacy

The ZIP contains the committed source tree and project/media assets, without Git
history. `RELEASE_MANIFEST.json` identifies the exact commit and SHA-256 of each file.
The sibling `.sha256` file verifies the complete archive. Archive CRC and every
manifest file hash are checked by `scripts/export_release.py`.

Excluded: real `.env` values, local agent settings, signed media download URLs,
database snapshots/dumps, runtime user uploads, issued certificates, private invoices
and ebooks, dependencies, caches, build output, raw duplicate capture files, and
nested release ZIPs. Original source labs, public product assets, final media and
creative source remain included. Runtime data is not a portable source-code backup.

Previously tracked local settings, runtime uploads and data artifacts are removed
from the new Git tree while left on disk. Existing remote Git history is not rewritten;
removing a file in this release does not remove it from earlier commits.
